# Session Flow 하네스 작성

이 작업 폴더에서 여러 세션이 나눠 일하고 있다. 지금의 실제 구성을 Session Flow 하네스 파일로 남긴다. 이 파일은 IDE의 Session Flow 화면에 그대로 그려지고, 각 세션에는 hook이 역할과 연락 대상을 안내한다.

## 파일

작업 폴더 루트의 `.claude/session-flow.json` (git 저장소면 저장소 루트):

```json
{
  "version": 2,
  "name": "<폴더 이름>",
  "enforce": false,
  "members": [
    { "name": "메인 핸들러", "role": "작업 분배와 결과 검토", "main": true },
    { "name": "GNN", "role": "GNN 학습·평가. 결과는 메인에 보고" }
  ],
  "edges": [
    { "from": "메인 핸들러", "to": "GNN" },
    { "from": "GNN", "to": "메인 핸들러" }
  ],
  "layout": {}
}
```

- `members[].name` 은 그 세션의 **/rename 이름 그대로**여야 한다. 이 이름이 SendMessage 수신 주소이기도 하다.
- `main` 은 하나만 true.
- `edges` 는 "먼저 보낼 수 있는" 방향이다. 받은 메시지에 대한 답장은 반대 방향이 없어도 허용된다. 비워두면 제한 없음.
- `enforce` 는 사용자가 명시적으로 원할 때만 true 로 한다(정한 방향 밖 메시지를 차단).
- 기존 파일이 있으면 `layout` 과 사용자가 적어둔 내용은 유지하고 필요한 부분만 고친다.

## 순서

1. 기존 `.claude/session-flow.json` 이 있으면 먼저 읽는다.
2. `ListAgents` 로 지금 이 머신에서 보이는 세션들과 이름을 확인한다. 이 작업 폴더(와 하위 폴더)에서 일하는 세션만 대상으로 한다. 다른 폴더의 세션은 넣지 않는다.
3. 이 대화에서 이미 알고 있는 분업(누가 무엇을 맡았는지, 누가 누구에게 지시·보고하는지)을 바탕으로 멤버, 역할, 메인, 방향을 정한다. 추측이 필요한 부분은 표시해 두고 사용자에게 확인한다.
4. 이름이 `kftc-3f` 처럼 자동으로 붙은 세션은 고정 이름이 아니라서 재시작하면 바뀐다. 이런 세션은 멤버로 넣되, 사용자에게 그 세션에서 `/rename <이름>` 을 실행해 달라고 목록으로 알려준다.
5. 파일을 쓰고, 사용자에게 멤버·역할·방향을 짧은 표로 보여준다. 차단은 켜지 않았다면 켜지 않았다고 말한다.

다른 세션의 대화 내용이나 파일은 이 작업에 필요한 만큼만 확인하고, 하네스 파일 외의 파일은 바꾸지 않는다.
